Bruno Collection Structure

collections/module4-filesystem/ ├── bruno.json # Collection metadata ├── environments/ # Environment variables │ ├── local.bru │ └── production.bru └── requests/ # API requests ├── 01-get-users.bru ├── 02-create-user.bru └── folders/ # Organized in folders └── auth/ └── login.bru

Key Benefits

🔄 Version Control

Easy Git integration for tracking changes and collaborating with teams.

👥 Team Collaboration

Share collections via Git repositories and merge changes easily.

📁 Organization

Folder structure for logical grouping of related requests.

💾 Portability

Works offline, no cloud dependency, complete control over your data.

File Formats

bruno.json

Collection configuration and metadata

{ "version": "1", "name": "My API Collection", "type": "collection" }

environment.bru

Environment variables and configuration

vars { baseUrl: http://localhost:8000 apiVersion: v1 authToken: your-token-here }

request.bru

Individual API request definition

meta { name: Get Users type: http seq: 1 } get { url: {{baseUrl}}/api/users body: none auth: none }

Best Practices

  1. Organize by Feature: Group related requests in folders
  2. Use Descriptive Names: Clear, meaningful request names
  3. Environment Separation: Different environments for different stages
  4. Documentation: Add docs to explain complex requests
  5. Version Control: Use Git to track changes and collaborate
